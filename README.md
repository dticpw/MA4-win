## 源码、配置与运行数据

| 项目 | Linux | Windows |
|---|---|---|
| 同一份源码 | `/mnt/e/PG/MA4-win` | `E:/PG/MA4-win` |
| 配置 | `config.json` + `config.linux.json` | `config.json` + `config.windows.json` |
| MA4 当前状态 | `/home/dticpw/PG_linux/MA4/.ma4` | `E:/PG/MA4-win/.ma4` |
| 默认传输 | `unix://` 原生控制 socket | `proxy://` 原生控制 socket |
| Python | `/home/dticpw/conda/envs/py310/bin/python` | `D:/python/anaconda/envs/th123/python.exe` |
| 启动入口 | 现有 `ma4.service` 用户服务 | 现有 `启动MA4.cmd` / `MA4.lnk`，手动启动 |

Codex 自己管理各系统的会话记录；MA4 只保存偏好、额度缓存及当前中控状态，不复制聊天正文。切系统不会迁移或继续另一侧的运行中任务。修改公共代码必须考虑两系统，另一侧无法实测的内容写入系统留言板；两侧不可并发写同一工作区。

默认配置中的 `app_server` 由 `codex_home` / 环境 CODEX_HOME / 本机用户目录派生出 `app-server-control/app-server-control.sock`。Windows 的 proxy 由 Codex CLI 提供，MA4 在其 stdin/stdout 上传输 **WebSocket 握手和帧**，不是 stdio JSONL。MA4 退出只关闭自己的连接代理，不停止原生 daemon。

`ws://127.0.0.1:8765` 仍可显式配置为独立 TCP 后台。连接失败不会自动切换传输或后台。通过 `--config <文件>` 指定的自定义配置是完整独立配置，不叠加本机默认配置；相对路径按该文件目录解析。`codex_bin` 可指定实际可执行程序，Windows 会将 npm CMD/PS1 包装器解析到同包 exe。自定义 CODEX_HOME 必须让网页、启动器和终端使用同一配置。

**会话共享边界：**「在终端打开」明确使用 MA4 的相同端点；普通终端和桌面 App 可能使用别的后台。能够读取同一 thread ID 的历史不代表能同时写入或实时收到事件。其他后台占用会话时返回明确的 409 提示，等待原客户端释放后重试；不抢占、不自动杀进程。

## 运行与维护

Linux 继续使用现有用户服务，不另起占用 8764 的进程。修改 Python 后，在共享目录完成相关检查，再执行 `systemctl --user restart ma4.service`；仅改 `web/` 刷新页面即可。查看状态用 `systemctl --user status ma4.service`，日志用 `journalctl --user -u ma4.service -n 50`。服务保留 `KillMode=process`，停止网页不连带停止 Codex daemon。

Windows 双击 `启动MA4.cmd`（或原有 `MA4.lnk`），准备原生后台和网页后以已安装 Chrome/Edge 应用窗口打开。重复点击复用实例；关闭窗口保留网页与后台。`停止网页.cmd` 仅停止本入口启动的网页；**默认原生 daemon 即使传入 `-IncludeBackend` 也不会停止**。该选项仅用于显式 TCP 模式下、本入口创建且进程身份吻合的后台。未新增登录自启、Windows 服务或定时任务，关机后需再次手动打开。

```powershell
# Windows 排查入口：只使用已安装 th123，-X utf8 保持中文一致
& 'D:/python/anaconda/envs/th123/python.exe' -B -X utf8 E:/PG/MA4-win/launch.py backend
& 'D:/python/anaconda/envs/th123/python.exe' -B -X utf8 E:/PG/MA4-win/launch.py web
```

原生模式的 backend 命令确认/按需启动 daemon 后退出；显式 TCP 模式保持窗口运行，关闭只终止它自己创建的进程。网页端口被无关进程或另一配置占用时拒绝启动，不替换原进程。

额度来源沿用各自运行目录的私有 `quota-source.json`，不写进 Git；Windows 未配置来源时显示无数据，须按凭据技能使用已有来源配置，不能复制 Linux 整个运行目录。服务活动只在内存保存当前结果；API 地址/条目名共用，凭据 CLI 和库路径分系统配置，不在日志或网页暴露口令。NTFS 上的 chmod 不能代替 Windows ACL。

## 共有功能

- 中控模式（2026-10-13 更新）：侧栏分「中控任务」「普通会话」两个页签。中控页按项目分组，展开查看当前中控、执行者及前任；同项目的旧普通会话只在普通页显示，不能凭工作目录把它们视为中控成员。日常普通会话直接列出，旧 RPGO3dPixel / MA3 会话折叠。
- 「＋ 中控」填写项目、名称和启动后时限（min），时限由用户填写，不预填；也可在其他预算限制中指定截止时间。初步想法可作为首条讨论消息。先与中控讨论，由它提交目标、范围和验收草案；用户在页面核对草案与预算后「确认并启动」。默认不设金额和 token 上限，创建时填写的预算保留到确认窗口；讨论不启动执行计时，但模型消耗计入总量。暂停、继续、交接或服务重启不重置已确定的截止时间。
- 草案与正式目标分开保存。新草案停止新增派工，已有执行者按原目标返回，预算仍有效；确认变更前不覆盖正式目标。可以只存草案，或确认保存但暂不启动。普通讨论不会恢复任务；到期收尾结束后可继续讨论，token / 金额硬上限仍须遵守。
- 对话区区分「你的消息」「MA4 自动通知」「执行者回报」，程序附带的目标/预算/状态默认折叠，可展开查看。旧消息只识别明确的程序模板，无法确定来源的标为「旧消息 · 来源未记录」，不补造来源记录。
- 附带内容保留完整目标与关键约束，只精简无关空闲执行者详情；非空闲、待回传或本条正文点名的执行者仍列出，完整列表可在任务页面或 `ma4_control(action=status).workers` 查询。程序确认/暂停/预算状态与目标原文分开说明，不自动重写已确认目标。
- 测试与独立验收指导：派工说明变更、受影响检查及已有证据；制作方相关自测，审查方核对方法与证据、抽查关键风险，不默认完整复跑。证据可读且相关实现、依赖、方法和条件仍匹配时复用；失败先最小复现和定点复测，风险扩散再扩大范围。交付区分新测、复用依据与未验证部分，当前验证说明沿用项目文档。指导随正常消息/派工更新，不增加审批或自动跳过测试。
- 中控通过三个专用工具派工、结束或交接、处理临时材料。执行报告在中控空闲时自动合并回传，不等其他目录的写入结束；中控忙碌时先保存、结束当前回合后再交付，不插入打断。任务面板显示待回传数量、等待原因和执行会话入口。回传消息列出仍在写入的具体路径，中控只验收已稳定且不受影响的产物，变化中的部分标为待验收；收到报告或本轮结束不等于目标达标。
- 不同中控任务预算独立；同一任务可管理多个已确认的工作目录，共用目标、预算和执行记录。确认窗口列出各目录及允许写入的相对路径，目录或范围变更先存草案，确认后才生效。执行者绑定实际 cwd，复用时不能换目录；省略 write_scope 继承该目录授权，显式空数组要求整个目录授权。写入冲突跨所有任务按实际路径检查，明确不重叠的范围可并行。中控主要制作与修改默认派给执行者，必要的核验和少量辅助操作可自行完成；范围是协作约定，不是 OS 隔离。
- 创建时可填启动后时长，或指定截止时间。已有截止时间的任务在确认窗口支持「从现在起的时限（min）」：填 30 表示从点击保存或确认时起 30 分钟到期，留空保留原截止时间，也可继续使用日历。可选设置中保留累计 token、按用户单价估算的金额上限；限制覆盖关联中控和执行会话。累计 token 包含缓存输入；有通知延迟及在途请求，不能保证精确截断消耗。
- 到达时限进入「到期收尾中」：停止新增派工与排队启动，给已有回合一次收尾提醒，等待自然结束。执行者返回后最多一次中控收尾汇总；当前中控没有待回传工作时直接等本轮结束。收尾时间和消耗可能超出时限，token / 金额硬上限及手动「立即停止」仍会请求中断；不会自动把到期收尾判成目标达标。
- 中控交接保留任务身份、目标、预算、执行会话与临时目录；新中控获得必要说明，旧判断仍需核实。无需复制完整聊天历史。
- 「临时材料」只处理本任务明确归属的精确路径，阻止符号链接、Windows Junction/reparse point、硬链接及运行中清理。必要文件需先转正，未知依赖保留并说明理由。任务完成时回收空临时目录。
- 「移除任务」要求停止运行并完成临时材料收尾；移除 MA4 关联并归档 Codex 会话，保留对话和正式项目文件。
- 中控优化（2026-10-13）：任务面板可展开中控/执行者、会话和轮次的用时与 token，非缓存输入、缓存输入、输出分列。结束记录保存验收结论、证据及收到的最终数字，收尾通知继续更新，不另开模型回合。旧任务没有补扫历史；未能归属的用量明确显示。
- 动态工具可展开查看参数、派工内容、返回值和失败原因；文本有长度限制，图片返回值只显示占位说明，不把图像数据再传入页面。

- 会话列表：读取最近更新的 80 条 Codex 会话，并补上守护进程中已载入的空白会话及本次服务运行期间新建/打开的会话；只补读元信息，排除子会话和临时会话。按「等你处理 / 运行中 / 新回复 / 置顶 / 其他」分组，显示目录和最后活动时间；搜索仅覆盖已加载的列表，尚未接入历史会话列表分页。
- 对话：历史记录，以及实时的逐字回复、命令和改文件记录。空闲时发送会开始新一轮，运行中发送会插进当前回合，也可以中断。
- 对话中的本地文件蓝字可点击或用键盘打开：由本机系统默认应用处理，HTML 交给浏览器，其他文件沿用系统关联；相对路径按所属会话的项目目录解析。支持中文、空格、`file://`、Windows 盘符转 Linux 挂载路径，以及 `:行号` / `#L行号` 引用（打开文件，不定位行号）。文件不存在或默认应用失败会提示；不会通过网页暴露本地文件目录。
- 新建普通会话默认目录为 `~/codex`（也可自行填写），`/new` 同样遵循此默认；既有会话工作目录不迁移。支持改名、置顶，以及「在终端打开」（用 `codex --remote <同一后台端点> resume` 接入同一会话）。
- 斜杠命令（2026-09-30 加入）：输入 `/` 弹出命令菜单，命令由 MA4 调用对应接口执行，不会当文字发给模型。
  - 已支持：`/rename`、`/compact`、`/model`、`/review`、`/stop`、`/new`、`/status`、`/skills`、`/help`。
  - 不认识的命令会被拦下；以 `//` 开头则把 `/` 当普通文字发送。
  - 单独输入 `/rename` 弹出改名框，也可输入 `/rename 新名称`；会话信息尚未载入时给出提示并保留输入。
- 标题栏显示模型、思考深度、Git 分支、权限模式（会话载入后才有）和上下文用量。
- 运行中的会话在列表和对话里显示已用时间和当前动作（如「执行 npm test」）；在终端里运行的会话也会被自动跟随。每一轮结尾显示开始时间和用时。`/model 模型名 [思考深度]` 从下一轮开始切换。
- Skill 附件必须主动选择：点「＋ Skill 附件」或输入 `$` 后从候选菜单选择，输入框上方显示可移除的「本条附加」标签。只输入/粘贴 `$名称` 并发送不会生成附件，候选默认不选中，直接 Enter 发送原文；点击候选、Tab 补全或方向键选中后 Enter 才附加。选择随当前会话草稿保存，发送成功清除、失败保留，下一条不继承。历史真实附件单独显示「Skill 附件：名称」，不再拼成正文末尾的 `@名称`；原生历史不改写。自动通知、执行报告、初步想法及执行派工均只发文字，MA4 不扫描文字生成附件；模型仍可依据用户指令或任务需要自行读取技能。
- 命令/文件审批沿用原有右侧入口；中控使用完全访问、从不审批，不再套用额外的 MCP 专用审批表单。

## 中控任务（现行方式）

1. 点「＋ 中控」，填写项目文件夹、任务名称及启动后时限（min，正整数）。时限不预填；经费默认不限，可在「其他预算限制」中设置金额、token 或明确截止时间。初步想法可留空；若填写，会作为第一条讨论消息发给中控，产生模型消耗但不启动自动执行。
2. 直接与中控商讨，让它提交目标、范围和验收草案。点「确认目标并启动」打开确认窗口，核对或修改草案及创建时保存的预算，再点「确认并启动」。也可「只存草案」或「确认保存，暂不启动」。默认不设金额和 token 上限，启动时按填写的时限生成固定截止时间；暂停、继续或交接不重新计时。已有截止时间时可填「从现在起的时限（min）」，例如 30 会改为点击保存/确认后 30 分钟到期，不在旧时间上累加；留空沿用日历中的时间。只存草案时记录固定时间，之后确认不再次顺延。未启动的时长预算仍可调整启动后时长，指定日期优先。token 是所有关联会话（含讨论）的累计用量，包含缓存输入；金额按自行填写的每百万 token 单价估算。
3. 需要跨项目时，让中控在草案中列出所需目录与写入范围，也可在确认窗口「本任务可用的工作目录」添加。主项目用于任务归类，不能移除；范围每行一个项目相对路径，留空允许整个目录。确认后中控直接复用授权，无需另建任务或重复确认；范围变更与目标变更一样会取消尚未执行的旧指令。页面「工作目录与执行范围」、派工返回值和执行者报告均显示实际目录。中控按需派发执行会话，等待由程序处理，检查实际成果后继续派工或明确结束。
4. 可随时暂停任务，暂停/到期后的普通讨论不恢复自动运行。新的目标先存草案，窗口对照显示原目标与草案；确认后才修改正式目标，并取消尚未执行的旧目标指令。草案更新时停止新增派工，已有回合仍受原预算限制，必须结束后才可确认。前任中控与执行会话只读查看，补充要求发给当前中控。
5. 上下文变长时请中控自行交接，或点「中控交接」填写必要说明。交接等待原中控结束本轮，不复制执行过程作为新中控的默认判断。
6. 在试验、验收、目标结束时处理「临时材料」。没有材料时无需额外工具调用；需要保留的记录理由。正式引用的材料先移到项目正式位置，再清理无依赖的临时文件。
7. 展开「用时与 token 统计」查看角色汇总与每个会话的轮次；旧数据与恢复缺口会标明，回合用时之和不等于实际等待时间。动态工具记录可展开看派工参数和失败原因。结束时由程序补记收到的收尾用量，不要求中控另开一轮更新数字。

目录授权不替代目标中的操作授权。旧目标若明确要求分为两个任务，应先修改对应草案并确认，不能因为程序支持跨项目就忽略旧约定。升级不会给已有任务添加目录、修改目标或恢复执行。

专用工具为 `ma4_dispatch`、`ma4_control`、`ma4_artifacts`。它们直接注入受管理的中控会话，无需更改用户全局 MCP 或 Codex 配置。派工记录是当前状态，不要求 Agent 建立领取/提交/签收文件。

直接使用 `/api/tasks/create` 只需 cwd/name，idea 为可选首条讨论消息；兼容传入的 target 仅作为草案，不能 create/start=true 一步执行。`/api/tasks/update` 保存草案，不修改正式目标；`/api/tasks/confirm` 需提供 task_id、最新 draft_revision、name、target、budget、start，表示用户明确确认所见内容。start=false 只确认保存，true 确认并启动；API 不把普通聊天当成确认。`/api/tasks/resume` 仅用于已有正式目标且无待确认草案的任务。省略预算仍默认两小时，durationMinutes 启动时转为 deadline；已有明确截止时间不因继续而重置。

跨目录接口沿用 update/confirm，增加 `workspaces: [{"cwd":"/实际绝对路径","write_scope":["相对路径"]}]`，包含主项目、最多 12 个目录。`write_scope: []` 明确授权整个目录。旧调用省略 workspaces 只保留原授权，若草案含未显示的目录变更则拒绝确认。`ma4_dispatch` 新工具可传 cwd；旧会话的工具 schema 不变，可把 `instruction` 第一行写为 `[MA4 工作目录] /实际绝对路径`，正文从下一行开始。旧/新中控均可在 `[MA4 目标草案]\n…` 末尾追加 `\n[MA4 工作目录]\n` 和上述完整 JSON 数组，由用户在页面核对后确认。普通任务不需要这些标记。

临时目录按实际项目分别使用 `.agent-tmp/ma4-<同一任务ID>/`，要求该项目 Git 已忽略 `.agent-tmp/`。临时材料工具聚合已使用目录，主项目沿用相对路径，其他项目返回完整路径；clean/keep 必须使用列表里的精确文件路径。撤回目录授权不遗失旧材料归属，移除任务前仍需完成各目录的材料收尾。不允许链接路径充当授权目录或写入范围；派工及排队启动前均复查。

实现边界：中控有完全访问能力，但以统筹和独立验收为主，制作与持续返工默认交给执行者；少量辅助写入须遵守已确认范围并避开在途写入。目录和 write_scope 是协作约定，不是 OS 沙箱。外部终端直接操作不受 MA4 写入排队控制。为避免单价失真，任务内暂不支持 `/model` 切换；同任务新会话保持中控创建时的模型，外部改模型且启用金额上限时暂停。

恢复累计用量时优先保留已收到的累计计数，并从相关 Codex 会话日志尾部最多读取 1 MiB 的 `token_count` 数字补齐服务离线期间的更新，不复制或输出正文。协议/日志格式不兼容时不编造用量，暂停提示核对。更完整的设计见 [DESIGN.md](DESIGN.md)。

## 中控派发（兼容直接 HTTP 调用）

另一个 Agent（如 Claude Code）当中控时，可以经 MA4 新建 Codex 会话派活：中控写任务单、审查结果，Codex 实现。会话是普通的 Codex 交互会话，用户在 MA4 里能实时看到过程，也能插话或中断。2026-10-01 首次实际使用（RPGO3dPixel 任务 001）。

**前提**

- 用户已明确同意这次派发，以及执行权限。Codex 按 `~/.codex/config.toml` 的默认设置运行（当前为完全访问、从不请求审批）；需要更严的权限时先和用户商量。显式 `workspace-write` 沙箱里 Godot 等图形程序打不开窗口，无法截图（2026-10-01 实测）。
- 派发消息应使执行者没有对话上下文也能读懂：目标、范围、硬约束与验收方法。复杂任务可引用项目内任务文档，简单任务不强制另建任务单。直接调用 `/api/new` 创建的是普通会话，不自动加入中控目标/预算管理。

**步骤**（写操作必须带 `X-MA4-Request` 头）

```bash
# 1. 新建会话并发出第一条消息；返回 {"threadId": ...}
curl -s --noproxy 127.0.0.1 -X POST -H 'Content-Type: application/json' -H 'X-MA4-Request: 1' \
  --data '{"cwd":"<项目目录>","text":"请执行要求……"}' http://127.0.0.1:8764/api/new
# 2. 起一个好认的名字
curl -s --noproxy 127.0.0.1 -X POST -H 'Content-Type: application/json' -H 'X-MA4-Request: 1' \
  --data '{"id":"<threadId>","name":"<项目> · <任务>"}' http://127.0.0.1:8764/api/rename
```

3. 等待：轮询 `GET /api/state`，找到该 `id` 的 `status`（running、approval、input、idle、error、offline 之一）。会话列表每 3 秒刷新，新建后先等它出现在列表里，再判断状态；`approval`、`input` 表示要人处理，`idle` 是这一轮结束，`error`、`offline` 要查原因。间隔 60 秒即可；Claude Code 用后台 Bash 的 until 循环，状态离开 running 时只通知一次。
4. 审查：读执行结果、`git status`/diff、截图，必要时亲自运行；在当前任务记录中保留必要结论。
5. 返工或补充要求：`POST /api/send`，内容 `{"id":"<threadId>","text":"……","request_id":"<唯一字符串>"}`。会话运行中发送会插进当前回合。

**边界**

- 派发方负责审查和收尾，Codex 自报「完成」不能代替审查。
- 不对同一工作区并发派多个会话，除非已经划分好文件范围或用了独立 worktree。
- Codex 运行期间，派发方不写它可能改动的同一批文件；补充要求走 `/api/send`。

## 文件与维护约定

- `hub.py` / `controllers.py` / `server.py` / `web/` 是公共业务，避免两系统各留一套实现。`runtime.py` 负责配置与调用系统接口，`os_adapters/` 负责差异；`desktop.py` / `launch.py` / `.cmd` / `.ps1` 是 Windows 启动入口，`deploy/ma4.service` 是 Linux 入口。
- `appserver.py` 共用 WebSocket/JSON-RPC；`paths.py` 共用目录边界与链接检查。Junction 检查兼容 Python 3.10，不依赖 3.12 的 is_junction。
- `activity.py` / `health.py` / `quota.py` 分别负责服务活动、站点健康和额度。`DESIGN.md` 与 `ARCHITECTURE.html` 解释既有中控设计，传输与路径的最新约定以本 README 为准。
- 正式源码、测试与当前验证说明留项目；临时输出 `.agent-tmp/<任务>/`，运行数据在上表各自目录，两类均不进 Git。没有持续同步、历史快照或完整会话副本。
- 新增/修改共享代码时同步有关测试和说明，提交前查看实际 Git 差异；仓库 `core.fileMode=false`，`.gitattributes` 保持 LF。
- 旧任务遗留的协议 schema 等仍按原记录保留，不能以这次迁移为由删除。迁移阶段没有 push、远程部署或全局 Codex/MCP 配置变更；后续 GitHub 公开发布见「现状与接续」。

## 与 MA3 的关系

日常中控默认用 MA4；只有用户明确说「MA3 的中控」才用 MA3。MA4 不依赖 MA3 服务，也不自动迁移其任务流转文件。相关项目展示见 [muQ MA4](https://muq.koa-ol.com/e/ma4/)。
